## 第九部分 · AI 应用前端与交互

### 33 流式渲染与布局稳定

- LLM 流式输出的 Layout Shift 如何解决？
  1. 为流式容器预留固定最小高度（min-height）或骨架屏，避免内容增长时推挤下方元素。
  2. 图片、代码块等异步资源预先设定宽高占位，防止加载完成后触发布局回流。
  3. 流式追加文本仅在容器内部增长，页面主体布局不随 token 到达而变化。
  4. 利用 CSS 的 overflow-anchor 或 contain 等属性限制重排范围。
  5. 移动端还需处理软键盘弹出导致的视口变化，并配合滚动位置修正。

### 34 聊天界面滚动与消息加载

- AI 聊天界面如何实现新消息平滑滚动，并兼容用户回看历史？
  1. 采用 stick-to-bottom 模式：仅当用户位于底部附近时，新消息到达才自动平滑滚动跟随。
  2. 用户向上滚动回看历史时立即停止自动跟随，并显示“回到最新”按钮。
  3. 判断依据通常使用 scrollTop 距底部距离的阈值，而非布尔状态，以避免临界抖动。
  4. 加载历史消息时锚定首条可见消息并补偿插入高度，保持阅读位置不跳动。
  5. 流式输出期间的滚动使用 requestAnimationFrame 或逐帧节流，避免每 token 滚动一次造成卡顿。

### 35 Markdown 渲染与代码块交互

- Markdown 代码块高亮与一键复制如何实现？
  1. 渲染管线：Markdown 解析器输出代码块节点，交由语法高亮库（highlight.js/Shiki/Prism 类）着色。
  2. 流式场景下代码块内容持续追加，需采用增量高亮或防抖后整体重高亮，避免每个 token 都触发重新解析。
  3. 复制按钮挂载于每个代码块头部，点击时通过 Clipboard API 写入剪贴板并给出已复制反馈。
  4. 渲染前对 HTML 进行转义，防止代码内容被当作标记执行而引发 XSS。

### 36 RAG 前端集成与交互

- RAG 流程中前端承担哪些职责？
  1. 流式渲染：逐 token 渲染回答，处理 Markdown 与代码块的渐进解析及排版稳定。
  2. 引用呈现：展示回答附带的引用来源（编号角标、来源卡片），支持点击跳转至原文档片段。
  3. 检索过程可视化：展示命中的知识片段与相关度，帮助用户理解答案依据。
  4. 反馈闭环：点赞点踩与答案不准确上报，回流至评测集。
  5. 异常态处理：检索为空、超时、低置信度时给出明确的前端提示，而非静默失败。

### 37 AI 前端性能监控指标

- AI 应用有哪些特有的前端性能监控指标？
  1. TTFT（Time To First Token）：首 token 延迟，直接决定用户感知的响应速度。
  2. 吞吐速率（tokens/s）：流式输出的稳定速度，过低会造成卡顿感。
  3. 流中断率与错误率：流式传输中途断开、触发重试的比例。
  4. 交互阻塞：流式渲染引发的长任务与掉帧，影响输入框响应。
  5. 端到端耗时分布（P50/P95/P99）：从提交到完整回答的时间，以及首次成功率。

### 39 视觉 Agent 与 GUI 操作

- 如何设计能理解并操作 GUI 界面的视觉 Agent？
  1. 视觉感知：截取屏幕图像，借助 VLM（SeeClick/CogAgent 类）识别按钮、输入框、菜单与文字，生成 UI 元素树或坐标标注。
  2. 意图理解：将“在购物网站搜索某商品”拆解为打开应用→定位搜索框→输入关键词→点击搜索的动作规划。
  3. 动作执行：将决策映射为 click(x,y)、type(text)、scroll(direction)、swipe(start,end) 等基本操作。
  4. 状态验证：每步执行后重新截屏确认操作生效（文字已输入、页面已跳转），失败则重试或重新规划。
  5. 核心难点：动态页面（弹窗、加载动画）干扰识别，VLM 坐标预测偏移导致误点，长任务链中误差逐步累积。
- 视觉 Agent 的评估体系与纯文本 Agent 有何不同？需要额外考虑什么？
  1. 提升视觉 Grounding 准确率：判断定位到的 UI 元素或物体 bounding box 是否正确（IoU 指标）。
  2. 空间推理：理解物体的相对位置关系（例如位于按钮右侧）。
  3. OCR 准确率：截图文字识别正确率，尤其关注小字体与艺术字体。
  4. 多帧一致性：在视频或动态场景中跨帧追踪同一物体的能力。
  5. 操作成功率：GUI 场景中每步操作是否真正命中目标元素并生效。
  6. 视觉幻觉需单独统计：模型看到图中不存在的物体或误读文字的情况。
  7. 常用 Benchmark：ScreenSpot（GUI 定位）、MMMU（多模态理解）、VisualWebArena（网页操作）；自动化测试可录制标准操作序列并与 Agent 行为比对，复杂场景仍需人工评估。

### 41 AI 前端安全与提示词注入防护

- 提示词注入（Prompt Injection）在前端层面如何防护？
  1. 核心原则：模型输出默认按纯文本或受控 Markdown 白名单渲染，绝不直接当作可信 HTML。
  2. 渲染前进行消毒：过滤 script、iframe、事件属性等危险节点，防止模型输出触发 XSS。
  3. 恶意注入常藏身于检索内容与网页内容中，前端应隔离展示外部内容的区域，不自动执行链接或自动填充表单。
  4. 敏感操作（授权、支付、发送数据）一律由前端二次确认，不依赖单一模型指令触发。
  5. 前端仅作为纵深防御的一环，根本防线仍在服务端的输入过滤与权限控制。
