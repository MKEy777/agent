## 目录行（大纲条目）说明

每个 `###`/`####` 小节内往往有若干**目录行**（形如 `- 关键词` 的无答案行，如 `- 状态持久化与 Checkpoint`、`- Embedding 模型选择`），它们是原文档的小节索引，**不属于任何具体问答条目**。维护时：
- 插入新问答时**不要改动这些目录行**；
- 判断某主题是否已存在时，目录行不算覆盖（见 write-note 技能规则），需匹配"`- 问题？` + 编号答案"形式的完整条目。

## 维护约定

1. **改内容只改本目录下的分部文件**，不要改 `docs/八股.md`（它是聚合产物）。
2. 每个分部文件内部结构：`- 面试问题？` 下一行缩进 `  1. 答案要点`，每条答案一句话（最多两句），保留关键术语与数字；与完整版风格一致。
3. 新增问答先做查重：搜索目标分部文件内是否已有同名或语义等价的完整条目，避免重复插入。
4. **先查后建，绝不硬塞**：只有主题与某 `#### x.y` 小节语义匹配才插入该小节；属于某章但无匹配小节时由 write-note 自动新建小节（`#### x.y`，编号自动分配）；主题完全超出本目录范围时自动新建分部文件（`NN-第X部分 · 名称.md`）。人工维护同样遵循：宁可新建小节/文件，也不要塞进主题无关的小节。
5. 需要完整单文件（如导出、整体检索、外部工具）时运行聚合脚本：
   ```bash
   python docs/八股/merge_all.py            # 聚合回 docs/八股.md
   python docs/八股/merge_all.py 任意路径.md  # 输出到自定义位置
   ```
   **自动识别，无需配置**：`merge_all.py` 会扫描本目录下所有 `NN-*.md` 分部文件（排除 `AGENTS.md`）并按序号聚合；新增/删除分部文件后直接重跑即可，不需要改任何代码或清单。写入统一为 UTF-8 无 BOM，读取自动剥离 BOM。
6. 重新拆分（如手动改坏了完整版）：
   ```bash
   python docs/八股/split_all.py            # 按 ## 部分重新拆回本目录
   ```
   拆分/聚合往返保证逐字节一致（忽略换行符差异）。

## 供智能体（write-note / 其他 agent）的定位指引

- 目标文档传 `docs/八股.md`（文件）→ 按单文件流程：三阶段提取→定位→润色，写入完整版（旧流程，大文档耗 token，仅用于临时场景）。
- 目标文档传 `docs/八股/`（目录）→ 按**目录模式**：跳过阶段1（输入一般是整理好的 Q&A），阶段2 只读取本 `AGENTS.md` + 目标分部文件的内容来定位章节（避免全量文档进 prompt），插入直接写回对应分部文件；有需要时再跑 `merge_all.py` 同步完整版。
- 定位规则：根据问题的主题词（如"MCP"→02 章→01 文件）先查上表选文件，再到该文件内匹配 `#### x.y` 小节。

## 注意事项

- `split_all.py` / `merge_all.py` 是本目录的工具脚本，聚合时会被排除（只拼 `.md`）。
- 文件名中的 `·`（间隔号）和空格保留，勿替换为下划线，聚合顺序依赖 `NN-` 前缀序号。
- 若某分部文件被误删，可用 `split_all.py` 从完整版重新生成。
